# v0.3.22 — TWS 10.53 compatibility fix

Fixes the native market-data accessors used for Time & Sales coloring after the TWS 10.53 update.

- Recognizes `jclient.dz.q8()` as the existing market-record getter, checking its return type and skipping the unrelated `rk()` and `q6()` methods.
- Recognizes `jclient.oQ.cO(): jclient.record.a0` as the top-of-book getter, with explicit class and return-type checks.
- Retains TWS 10.51 and 10.52 accessor support, historical-row neutrality and frozen per-trade quotes.
- Updates the optional accuracy audit, versioned agent classes, Windows launcher, documentation and bundled distribution.

Validation: all 18 Java test programs and six Python tests passed. The live audit tools compile, the packaged JAR passes the version smoke test with JVM verification enabled, and its SHA-256 checksum matches. TWS 10.53.1a installed bytecode was inspected. Live attachment/rendering on 10.53 and Windows operation remain unverified.

**Upgrade:** restart TWS before switching from a previously loaded agent. Use `twstapecolor-v0.3.22.jar` with JDK 21+, or rebuild from source with `./build` and run `./twstapecolor start`.

Release assets: `twstapecolor-v0.3.22.jar` and `SHA256SUMS` from `dist/`.
