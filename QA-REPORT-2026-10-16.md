# Symbol-switch regression fix — v0.3.18

Tested on 2026-10-16 in the user's running TWS on JDK 25.0.2, using the live Hong Kong SEHK session and the existing 1810 / 9988 symbol history. No orders, link preferences or depth subscriptions were changed. The final session was returned to 1810 with coloring enabled.

## Reproduced failure and correction

With coloring disabled, normal symbol selection updated the linked tape/depth selectors and new tape rows arrived. With v0.3.16 enabled, switching the tape from 9988 to 1810 reproduced the reported failure: the tape selector reached 1810, the depth selector stayed on 9988, and history emptied while Current kept receiving updates.

An opt-in EDT exception probe captured `IndexOutOfBoundsException: Invalid range` in `DefaultRowSorter.rowsUpdated`, followed by `ArrayIndexOutOfBoundsException` in its incremental insertion mapping. The stack passed through the native tape's symbol/time-zone and indicative-contract callbacks. Those exceptions interrupted TWS's linked-window processing. Stopping the agent and selecting the contract again restored normal native operation.

The fix:

- Native history uses a private sorter that rebuilds from the current model on update/insert/delete notifications. It does not assume TWS follows Swing's incremental row-event contract during resets.
- A model-to-view guard handles newly grown or stale indices during Swing's repaint-before-sorter-notification path. A seeded stress test found this second path; it is covered in the final build.
- Current keeps TWS's original row handling and receives no private sorter. Its coloring still uses its own captured quote when available.
- Watched market records rotate at the existing 64-record bound. New symbols no longer lose quote capture after the bound is reached. Retained trades keep their frozen quotes.
- Captured events are checked against their instrument record, price and size. A reused event object cannot inherit another instrument's captured quote.

The renderer paint isolation, stronger v0.3.16 shades, 50-history-trade cap, opt-in diagnostics, restart-safe helper names and MIT license remain intact. Quote-only events remain in the model.

## Live symbol-switch matrix

The final build passed **11 live observation phases**: repeated 1810/9988 switches from both native selectors, a same-symbol reselection, and a rapid 9988-to-1810 round trip. The optional driver selected existing SEHK entries through the real Swing combo's selection event, matching the native history-menu path.

Each phase required:

- Both native tape/depth selectors, Current and history agreed with the requested instrument after native transfer.
- Every retained history event belonged to that instrument; Current had no private sorter and history mappings remained in bounds.
- At least two captured trade events were present and the newest native history identity advanced during observation. Current-only refreshes and historical rows alone could not pass.

All 11 phases had **zero post-settlement header mismatches, history-instrument mismatches and audit errors**. They contained **13 observed history advances**. The first sampled state was settled at 250 ms in each final phase; this is sampling resolution, not a timing guarantee. Retained history repopulated and eventually returned to the native model's 17 rows in this layout. The EDT probe recorded **zero unhandled exceptions** with the final build.

Preliminary measurements informed the test harness: one eight-second interval contained only one new trade and was extended rather than counted as proof of continued history. Another observed one quarter-second sample of old history after combo captions changed but before TWS cleared/transferred its models. The final audit records this asynchronous transition separately and checks for regressions after settlement; the raw preliminary evidence is retained locally.

## Restoration, continued arrivals and resource checks

Three stop/start cycles each matched all **42 compared stable native table properties and normalized method fingerprints**, with zero mismatches and zero tool call instructions left in the three target methods. A separate restart observation confirmed new captured 1810 history events and further history advancement after re-enabling. The final compiled production class bytes matched the version-specific JAR used in the live tests.

A bounded 1 Hz resource sampler observed 45 disabled samples and 90 enabled samples. Read-only switch observations were present briefly at the start of these intervals; no live GC was forced. These are whole-TWS measurements, with changing market activity, and do not establish causal CPU savings.

| Measurement | Disabled | Enabled |
| --- | ---: | ---: |
| Average process CPU, cores | 0.165 | 0.126 |
| Heap-used range, MiB | 220–567 | 223–610 |
| EDT queue delay, 95th percentile | 0.160 ms | 0.158 ms |

Enabled tool caches ended at **2 views, 117 trades, 1 watched quote record and 1 current trade**. Retained trade/record bounds remain 4,096 / 64 and reset/eviction queues are cleared on stop. Heap rose between ordinary collections, so this short sample alone is not a long-term leak test. It showed no UI responsiveness regression or runaway tool-cache growth. The headless constrained-heap tests and the prior million-paint test add bounded-allocation coverage.
